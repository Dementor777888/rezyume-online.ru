# ROADMAP.md — порядок разработки «Резюме Онлайн»

## Цель дорожной карты

Дорожная карта нужна, чтобы Codex и разработчик двигались маленькими проверяемыми срезами, а не пытались собрать весь SaaS за один проход.

## Фаза 0 — подготовка репозитория

Цель: создать технический каркас, в который можно безопасно переносить дизайн и бизнес-логику.

### Результат фазы

- Next.js 15 App Router.
- TypeScript strict.
- Prisma + MariaDB.
- Tailwind или CSS Modules с токенами дизайн-системы.
- Базовый layout.
- Подключены шрифты с кириллицей.
- Есть `.env.example` или документированный набор env-переменных.
- Есть healthcheck route.
- Есть seed-команда.

### Не входит

- оплата;
- кабинет;
- AI;
- SEO-каталог;
- админка;
- DOCX.

## Фаза 1 — бесплатный вертикальный срез MVP

Цель: пользователь может создать резюме и скачать PDF бесплатно.

### Состав

1. Контракт `Resume.data`.
2. Zod-валидация данных резюме.
3. Конструктор 6 шагов:
   - Контакты;
   - Опыт;
   - Образование;
   - Навыки;
   - Фото;
   - Шаблон.
4. Черновик в localStorage.
5. Live preview справа на десктопе.
6. Preview в нижней модалке на мобайле.
7. Два бесплатных шаблона:
   - `start`;
   - `start_photo`.
8. Сохранение анонимного `Resume` в БД.
9. Бесплатный PDF export.
10. Публичная ссылка на 24 часа.
11. Обязательное согласие на обработку ПДн перед созданием резюме.
12. Отдельная опциональная галочка публикации в Базе резюме, выключена по умолчанию.

### Критерий готовности

Пользователь с чистой сессией может открыть сайт, заполнить форму, увидеть preview, скачать PDF с кириллицей и открыть публичную ссылку.

## Фаза 2 — платные шаблоны и DOCX

Цель: создать ценность платного пакета без подключения оплаты.

### Состав

1. Пять paid-шаблонов:
   - `clean`;
   - `compact`;
   - `one_column`;
   - `academic`;
   - `accent`.
2. Акценты:
   - `blue`;
   - `teal`;
   - `graphite`.
3. Галерея шаблонов.
4. Переключение шаблонов на своих данных.
5. DOCX export для paid-резюме.
6. Блокировка DOCX для free с честным объяснением: «DOCX входит в AI-версию · 99 ₽».

### Критерий готовности

Один и тот же `Resume.data` корректно рендерится в 7 шаблонах, PDF и DOCX открываются с кириллицей.

## Фаза 3 — YooKassa, промокоды, paid-активация

Цель: подключить честную разовую оплату.

### Состав

1. Email перед оплатой.
2. Создание или поиск `User` по email.
3. Создание `Payment` со статусом `pending`.
4. Создание платежа YooKassa на 9900 копеек.
5. Промокоды:
   - `free_access`;
   - `percent`;
   - `fixed`.
6. Webhook YooKassa.
7. Идемпотентность по `providerPaymentId`.
8. Активация резюме после `payment.succeeded`:
   - `tier = paid`;
   - `expiresAt = null`;
   - `userId = User.id`;
   - PDF/DOCX доступен без лимита.
9. Письмо после оплаты:
   - пароль от ЛК;
   - ссылка на резюме;
   - ссылки на файлы или уведомление о готовности файлов.

### Критерий готовности

Тестовый платеж активирует paid-резюме ровно один раз, повтор webhook не создаёт дублей и не ломает статус.

## Фаза 4 — личный кабинет

Цель: paid-пользователь может вернуться и управлять резюме.

### Состав

1. Login email/password.
2. Восстановление пароля.
3. HttpOnly cookie session.
4. Страница «Мои резюме».
5. Карточки резюме:
   - миниатюра;
   - название;
   - статус;
   - публичная ссылка;
   - редактировать;
   - скачать PDF;
   - скачать DOCX;
   - поделиться.
6. Несколько резюме на аккаунт.

### Критерий готовности

Пользователь после оплаты входит в кабинет, видит резюме, редактирует его, скачивает PDF/DOCX заново без новой оплаты.

## Фаза 5 — контент, SEO и админка

Цель: заложить органический трафик и управление контентом.

### Состав

1. `/primery/`.
2. `/primery/[section]/`.
3. `/primery/[section]/[profession]/`.
4. `/shablony/`.
5. `/shablony/[template]/`.
6. `/stati/`.
7. `/stati/[slug]/`.
8. `/faq/`.
9. Sitemap.
10. Robots.
11. Schema.org для FAQ и страниц профессий.
12. Админка:
    - промокоды;
    - профессии;
    - статьи;
    - FAQ;
    - служебные страницы;
    - meta title/description.

### Критерий готовности

Можно создать раздел, профессию, статью и FAQ в админке; публичные страницы доступны, индексируемы и попадают в sitemap.

## Фаза 6 — AI-фото

Цель: подключить первую AI-фичу платного пакета.

### Состав

1. Upload фото.
2. Валидация типа и размера.
3. Кроп.
4. Сохранение original.
5. Вызов Gemini/Nano Banana.
6. Сохранение enhanced.
7. UI «до → после».
8. Fallback при ошибке API: оставить original, не блокировать экспорт.
9. Rate limit.

### Критерий готовности

Пользователь с paid-доступом может улучшить фото; при ошибке AI сервис остаётся работоспособным.

## Фаза 7 — AI-ввод, импорт, ATS

Цель: развивать paid-пакет после стабильного MVP.

### Состав

1. Голосовая надиктовка.
2. AI-разбор по полям.
3. Импорт старого резюме PDF/DOCX.
4. AI-усиление формулировок.
5. ATS-проверка.
6. Подгонка под вакансию.
7. Cover letter.
8. «Честный разбор».

### Критерий готовности

Каждая AI-фича добавляется отдельно и появляется в UI только после реализации backend.
