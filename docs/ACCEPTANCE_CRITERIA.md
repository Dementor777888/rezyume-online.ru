# ACCEPTANCE_CRITERIA.md — критерии приёмки MVP

## 1. Главный пользовательский сценарий Free

Сценарий:

1. Пользователь открывает сайт.
2. Нажимает «Создать резюме бесплатно».
3. Заполняет 6 шагов конструктора.
4. Видит live preview.
5. Принимает согласие на обработку ПДн.
6. Не ставит публикацию в Базе резюме.
7. Скачивает PDF бесплатно.
8. Получает публичную ссылку на 24 часа.

Критерии:

- регистрация не требуется;
- PDF скачивается без оплаты;
- PDF не содержит водяного знака;
- кириллица в PDF корректная;
- публичная ссылка открывается;
- на free-ссылке видна плашка про 24 часа;
- после истечения срока ссылка не раскрывает резюме;
- draft восстанавливается после перезагрузки страницы.

## 2. Главный пользовательский сценарий Paid

Сценарий:

1. Пользователь создал или заполнил резюме.
2. Выбирает paid-шаблон или DOCX.
3. Видит честный блок «AI-версия · 99 ₽ один раз, без подписки».
4. Вводит email.
5. Применяет промокод или переходит к YooKassa.
6. Успешно оплачивает.
7. Резюме становится paid.
8. Пользователь получает письмо.
9. Входит в кабинет.
10. Скачивает PDF/DOCX повторно без новой оплаты.

Критерии:

- цена видна до оплаты;
- нет автоподписки;
- нет предвыбранных платных опций;
- Payment создаётся в БД;
- webhook активирует paid один раз;
- `Resume.tier = paid`;
- `Resume.expiresAt = null`;
- paid-ссылка бессрочная;
- пользователь видит резюме в кабинете;
- PDF и DOCX доступны повторно без оплаты.

## 3. Конструктор

Критерии:

- есть 6 шагов:
  - Контакты;
  - Опыт;
  - Образование;
  - Навыки;
  - Фото;
  - Шаблон.
- можно добавить несколько мест работы;
- можно удалить место работы;
- можно добавить образование;
- можно добавить навыки;
- можно загрузить фото;
- шаблон выбирается на своих данных;
- preview обновляется при вводе;
- ошибки валидации видны рядом с полями;
- на мобайле preview доступен через нижнюю модалку/drawer.

## 4. Шаблоны резюме

Критерии:

- 2 free-шаблона доступны без оплаты:
  - `start`;
  - `start_photo`.
- 5 paid-шаблонов доступны после оплаты:
  - `clean`;
  - `compact`;
  - `one_column`;
  - `academic`;
  - `accent`.
- Paid-шаблоны поддерживают акценты:
  - blue;
  - teal;
  - graphite.
- Один `Resume.data` рендерится во всех шаблонах.
- Длинные блоки опыта не наезжают друг на друга.
- Фото не ломает сетку.
- Academic-шаблон корректно работает без фото.

## 5. PDF

Критерии:

- PDF генерируется через Playwright.
- Используется тот же React-шаблон, что и preview.
- A4-разметка стабильная.
- Кириллица корректная.
- Файл открывается в Chrome, Edge, Acrobat Reader.
- Повторная генерация использует кэш, если резюме не менялось.
- При изменении данных кэш инвалидируется.
- Free PDF доступен без оплаты.

## 6. DOCX

Критерии:

- DOCX генерируется через `docx`.
- DOCX доступен только paid.
- Free получает понятное сообщение о paid-фиче.
- Кириллица корректная.
- Файл открывается в Microsoft Word и LibreOffice.
- Повторная генерация использует кэш, если резюме не менялось.

## 7. YooKassa

Критерии:

- сумма платежа 9900 копеек до промокодов;
- валюта RUB;
- Payment создаётся со статусом `pending`;
- `providerPaymentId` сохраняется;
- webhook повторно безопасен;
- `payment.succeeded` активирует paid;
- `payment.canceled` не активирует paid;
- промокод `free_access` активирует paid без YooKassa;
- скидки percent/fixed корректно меняют сумму;
- секреты YooKassa не попадают в frontend.

## 8. Auth и кабинет

Критерии:

- User создаётся при оплате;
- пароль генерируется и хэшируется bcrypt;
- пароль отправляется на email;
- login работает;
- logout работает;
- recovery работает;
- session хранится в httpOnly cookie;
- пользователь видит только свои резюме;
- admin не смешивается с обычным user.

## 9. Privacy и 152-ФЗ

Критерии:

- обязательное согласие на обработку ПДн блокирует экспорт, если не принято;
- публикация в Базе резюме выключена по умолчанию;
- согласие на распространение ПДн отдельное;
- контакты в Базе резюме скрыты;
- пользователь может отозвать публикацию;
- free/share-link и база реальных резюме не смешиваются;
- публичные SEO-примеры используют вымышленные данные.

## 10. SEO

Критерии:

- landing доступен на `/`;
- `/primery/` работает;
- `/primery/[section]/` работает;
- `/primery/[section]/[profession]/` работает;
- `/shablony/` работает;
- `/stati/` работает;
- `/faq/` работает;
- meta title/description есть;
- sitemap генерируется;
- robots закрывает drafts/private/admin;
- страницы профессий можно генерировать SSG/ISR.

## 11. Админка

Критерии:

- admin login работает;
- есть CRUD промокодов;
- есть CRUD профессий;
- есть CRUD статей;
- есть CRUD FAQ;
- есть CRUD служебных страниц;
- можно редактировать meta title/description;
- обычный user не имеет доступа к admin.

## 12. Производительность

Критерии:

- landing загружается без тяжёлого JS конструктора;
- конструктор не тормозит на резюме с 10 местами работы;
- PDF генерируется за разумное время на production-сервере;
- Playwright не запускает новый browser на каждый запрос без необходимости;
- SEO-страницы отдаются статически или через ISR;
- файлы PDF/DOCX не генерируются повторно без изменений.

## 13. Безопасность

Критерии:

- нет SQL injection за счёт Prisma;
- все входы валидируются;
- upload ограничен по типу и размеру;
- нельзя прочитать чужой PDF/DOCX по перебору имени файла;
- publicToken достаточно длинный и случайный;
- editToken не хранится в БД открытым текстом;
- секреты не логируются;
- webhook endpoint не раскрывает подробности ошибок наружу;
- admin защищён ролью и желательно IP allowlist.

## 14. Demo script для проверки MVP

Проверить вручную:

1. Открыть `/`.
2. Перейти в `/constructor`.
3. Заполнить данные Анны Соколовой из фикстуры.
4. Выбрать шаблон `start`.
5. Скачать PDF.
6. Открыть PDF и проверить кириллицу.
7. Открыть публичную ссылку.
8. Перезагрузить страницу конструктора и проверить localStorage draft.
9. Попробовать DOCX без оплаты и получить paid-сообщение.
10. Провести тестовую оплату YooKassa.
11. Проверить paid-шаблон `clean`.
12. Скачать DOCX.
13. Войти в кабинет.
14. Скачать PDF/DOCX повторно.
