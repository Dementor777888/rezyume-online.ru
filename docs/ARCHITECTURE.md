# ARCHITECTURE.md — Резюме онлайн

> Технический слой. Опирается на `PRD.md` и `design_system/`. Железо: выделенный сервер i5-12600 (12 ядер), 32 GB RAM (~25 свободно), 910 GB SSD, Debian 12 + ispmanager, MariaDB установлена. Всё хостится на этом сервере, внешних БД нет.

---

## 1. Принципы

1. Простота выше «правильности». Один сервер, один процесс приложения, одна БД. Без очередей, без микросервисов, без Kubernetes.
2. Один код шаблонов резюме для всего: превью в браузере, PDF, публичная страница. Дизайн-система уже в React — этим пользуемся.
3. Нагрузка низкая (единичные одновременные генерации) — синхронная обработка, без воркеров.
4. Все ПДн — на нашем сервере (152-ФЗ, локализация).

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Приложение | **Next.js 15 (App Router) + Node.js 22 LTS** | Фронт+бэк+SSR в одном. SSR/SSG обязателен для SEO-каталога (500+ страниц профессий). Дизайн-система уже на React — шаблоны переносятся напрямую |
| БД | **MariaDB (существующая)** | Уже стоит, задач хватает с запасом. Docker-альтернативы не нужны |
| ORM | **Prisma** | Схема = документация, миграции, MySQL/MariaDB-диалект поддержан |
| PDF | **Playwright (Chromium, warm instance)** | Рендерим те же React-шаблоны → HTML → PDF. Кириллица решается подключением шрифтов (Golos Text, PT Serif) в CSS печати. Один источник истины для превью и файла |
| DOCX | **docx (npm)** | Программная сборка DOCX по данным резюме, шаблон-маппинг на 7 пресетов |
| Фото AI | **Google Nano Banana (Gemini API)** | Уже выбрано. Синхронный вызов, таймаут 30 c, фолбэк «оставить как есть» |
| Оплата | **YooKassa API + вебхуки** | Модуль из готового SaaS (см. `reuse-map.md`) |
| Email | **SMTP** (почта домена через ispmanager или Unisender/Mailganer для рассылок) | Транзакционные: пароль от ЛК, файлы, ссылки. Рассылка «новые резюме» — отдельно, double opt-in |
| Процесс | **pm2** (systemd-уровень) | Рестарт, логи, zero-downtime reload |
| Веб-вход | **nginx (управляется ispmanager) → reverse proxy на Node :3000** | ispmanager остаётся для почты/DNS/SSL (Let's Encrypt), приложение живёт своим процессом |
| Хранение файлов | Диск: `/var/www/rezyume/storage/{photos,pdf,docx}` | 910 GB хватит на годы. PDF/DOCX генерируются и кэшируются, инвалидация при правке резюме |

Без Docker: на этом сервере он не даёт выгоды, только слой сложности поверх ispmanager. Если позже понадобится изоляция — приложение переезжает в compose без изменений кода.

## 3. Компоненты

```
nginx (443, SSL, static cache)
  └─ Next.js app (pm2, :3000)
       ├─ Pages (SSR/SSG): лендинг, SEO-каталог, статьи, FAQ, публичные резюме
       ├─ App (CSR): конструктор, кабинет, админка
       ├─ API routes: /api/resume, /api/payment, /api/photo, /api/export, /api/auth, /api/admin
       ├─ Renderer: Playwright warm instance (PDF)
       └─ Prisma → MariaDB (localhost)
Файлы: /var/www/rezyume/storage
Крон: node-cron внутри приложения (очистка 24ч-ссылок, digest подписки, бэкап-дамп)
```

## 4. Ключевые потоки

**Бесплатное резюме:** конструктор (черновик в localStorage) → на последнем шаге POST /api/resume (создаётся анонимная запись + токен ссылки) → рендер PDF → выдача файла + ссылка на 24 ч. Крон удаляет просроченные анонимные резюме (сутки + грейс 7 дней).

**Оплата:** email → создание User (пароль генерится, хэш bcrypt, письмо) → создание Payment (pending) → редирект/виджет YooKassa → вебхук `payment.succeeded` → активация AI-версии у резюме → письмо с файлами и паролем. Идемпотентность вебхука по `payment_id`. Резюме привязывается к User, ссылка становится бессрочной.

**AI-фото:** upload → валидация (тип/размер ≤15 MB) → Gemini API → сохранение оригинала и улучшенного → пользователь выбирает. Ошибка API не блокирует флоу.

**Экспорт:** PDF — Playwright печатает страницу `/print/resume/[id]?template=X` (тот же React-шаблон, print-CSS, A4, ширина макета 620px по dev-notes). DOCX — сборка через docx из тех же данных. Кэш файла до изменения резюме.

**SEO-каталог:** страницы разделов/профессий — SSG + ISR (revalidate при правке в админке). Контент и меты редактируются в админке (title/description в БД — по design-handoff). Детали — `seo-catalog.md`.

## 5. Безопасность и 152-ФЗ

- Все ПДн в MariaDB на этом сервере; сервер должен физически находиться в РФ (проверить у хостера — требование локализации).
- Пароли — bcrypt; сессии — httpOnly cookie (NextAuth/lucia или своя, из reuse).
- Публикация в Базе резюме: флаги `is_public`, `consent_distribution` (версия+дата текста согласия), маска полей; контакты видны только роли «работодатель» (см. `data-model.md`).
- Rate limit на /api/photo и /api/export (nginx limit_req) — защита от выжигания квоты Gemini.
- Админка — отдельный логин + IP-allowlist в nginx (опционально).
- Бэкапы: nightly mysqldump + tar storage → отдельный диск/внешнее хранилище, ротация 14 дней.

## 6. Производительность (оценка под железо)

- Playwright warm instance: ~300–500 MB RAM, генерация PDF 1–3 с. 12 ядер и 25 GB — запас на порядки выше нужного.
- SSG-каталог отдаётся nginx-ом как статика — SEO-трафик не грузит Node.
- MariaDB: базы на десятки тысяч резюме — ничтожная нагрузка.
- Узкое место — только внешние API (Gemini, YooKassa): таймауты и ретраи, UI показывает состояние.

## 7. Чего НЕ делаем

- Очереди (Redis/BullMQ), воркеры, отдельные сервисы — нагрузка не требует.
- Docker в проде — ispmanager+pm2 проще.
- S3/объектное хранилище — локальный диск.
- Микрофронтенды, GraphQL, серверless.

## 8. Открытые вопросы

1. Подтвердить географию сервера (РФ) — критично для 152-ФЗ.
2. SMTP для рассылок: свой (риск спам-фильтров) или Unisender — решить до Шага 3.
3. Node на сервере: поставить 22 LTS через nvm/apt (ispmanager сам не управляет Node-приложениями — проксируем вручную через «WWW → доп. конфиг nginx»).
