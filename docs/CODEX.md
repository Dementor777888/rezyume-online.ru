# CODEX.md — правила работы Codex в проекте «Резюме Онлайн»

## 1. Контекст проекта

Проект: `rezyume-online.ru`.

Строим русскоязычный SaaS-сервис для создания резюме:

- бесплатный контур: конструктор, 2 шаблона, PDF, ссылка 24 часа, без регистрации;
- платный контур: «AI-версия · 99 ₽» одним платежом, без подписки;
- в платный контур входят 5 дополнительных шаблонов, DOCX, бессрочная ссылка, личный кабинет, AI-фото, позже голос, импорт, AI-формулировки, ATS и сопроводительное письмо.

Главный рыночный дифференциатор: честная разовая оплата, без скрытой подписки.

## 2. Приоритет источников истины

При конфликте документов использовать такой порядок:

1. `docs/CODEX.md` — правила разработки и запреты.
2. `docs/PRD.md` — продуктовые требования и скоуп.
3. `docs/ARCHITECTURE.md` — стек, продовая архитектура, ограничения.
4. `docs/data-model.md` — Prisma-модель и сущности.
5. `docs/RESUME_DATA_CONTRACT.md` — структура `Resume.data` и валидация.
6. `design_system/` — визуальная система, компоненты, токены, шаблоны, скриншоты.
7. `docs/DESIGN_IMPLEMENTATION.md` — порядок переноса дизайна в production.
8. `docs/API.md` — API-контракты.
9. `docs/reuse-map.md` и `docs/DONOR_REUSE_PLAN.md` — правила переиспользования кода старого SaaS.
10. `docs/seo-catalog.md` — SEO-структура.

Если найдено противоречие, не придумывать новую архитектуру. Внести минимальное изменение в профильный документ и затем писать код.

## 3. Стек, который нужно использовать

- TypeScript strict mode.
- Next.js 15 App Router.
- React.
- Node.js 22 LTS.
- MariaDB.
- Prisma.
- Playwright Chromium для PDF.
- `docx` для DOCX.
- YooKassa для разовых платежей.
- SMTP для транзакционных писем.
- pm2 для production-процесса.
- nginx reverse proxy через ispmanager.
- Local filesystem storage: `/var/www/rezyume/storage/{photos,pdf,docx}`.

## 4. Запрещено добавлять без отдельного решения владельца проекта

Нельзя добавлять:

- Docker в production;
- Kubernetes;
- микросервисы;
- Redis;
- BullMQ;
- очереди и воркеры;
- GraphQL;
- PostgreSQL вместо MariaDB;
- внешнюю managed database;
- S3/объектное хранилище для MVP;
- рекуррентные платежи;
- подписки;
- пользовательские балансы;
- кошельки;
- тарифную сетку с несколькими платными планами;
- OAuth-стену до первого результата;
- фейковые таймеры;
- предвыбранные галочки согласий;
- платный запрет на скачивание базового PDF;
- AI-фичи в UI, если backend для них ещё не реализован.

## 5. Правила монетизации

Единственный платный пакет: `AI-версия · 99 ₽`.

Технически сумма хранится в копейках:

```text
9900
```

Оплата:

- только разовая;
- без автопродления;
- без сохранения карты для рекуррента;
- привязана к конкретному `Resume`;
- после успешного платежа `Resume.tier = paid`, `Resume.expiresAt = null`;
- повторные правки и скачивания бесплатны.

## 6. Правила работы с донором старого SaaS

Донор старого SaaS разрешено использовать только как read-only источник.

Фактический путь донора:

```bash
/home/axel/code/_donors/imgfactory
```

Windows UNC-путь для справки:

```text
\\wsl.localhost\Ubuntu\home\axel\code\_donors\imgfactory
```

В Bash/WSL использовать только Linux-путь.

Разрешено смотреть и адаптировать:

- YooKassa client;
- создание платежа;
- webhook;
- идемпотентность;
- промокоды;
- bcrypt/password utils;
- session utils;
- SMTP/email utils;
- rate-limit подходы.

Запрещено переносить из донора:

- подписки;
- рекуррентные списания;
- балансы;
- кошельки;
- лимиты как пользовательскую валюту;
- очереди;
- воркеры;
- старые тарифы;
- старую БД без адаптации к `data-model.md`;
- старый UI оплаты, если он конфликтует с дизайн-системой.

## 8. Порядок разработки

Сначала сделать рабочий вертикальный срез:

```text
конструктор → Resume.data → live preview → сохранение → PDF → публичная ссылка 24 часа
```

Затем:

1. paid-шаблоны;
2. DOCX;
3. YooKassa;
4. промокоды;
5. auth и кабинет;
6. email;
7. SEO-каталог;
8. админка;
9. AI-фото;
10. голос/импорт/ATS.

## 9. Минимальные стандарты кода

- Все публичные входы валидировать через zod.
- Все API-ответы возвращать в едином формате из `docs/API.md`.
- Не хранить пароли в открытом виде.
- Сессии только через httpOnly cookie.
- Не логировать ПДн, пароли, токены, webhook secret, YooKassa credentials.
- Все пути storage строить через безопасные server-side функции.
- Не принимать произвольный путь файла от клиента.
- PDF/DOCX должны корректно отображать кириллицу с первого дня.
- Компоненты резюме должны переиспользоваться для preview, print page и public page.

## 10. Definition of Done для любой задачи

Задача считается готовой, если:

- код компилируется;
- TypeScript не содержит ошибок;
- базовый happy path работает вручную;
- обработаны ошибки пользователя;
- нет противоречия с PRD/ARCHITECTURE/data-model;
- UI не нарушает дизайн-токены;
- нет скрытых подписок, предвыбранных согласий и фейковых таймеров;
- изменения отражены в профильном doc-файле, если контракт поменялся.
