# seo-catalog.md — Резюме онлайн

> SEO-каталог — основной генератор органического трафика. Опирается на `PRD.md` (разд. 5, 9), `data-model.md`, `ARCHITECTURE.md`. Дизайн — экраны Examples/ResumeBase/Articles в `design_system/`.

---

## 1. Два разных актива (не путать)

1. **Примеры резюме по профессиям** — обезличенный SEO-контент. Вымышленные данные, ПДн нет, согласие не нужно. Главный источник трафика. Целевой объём: 17 разделов · 500+ профессий.
2. **База резюме** — реальные резюме пользователей, опубликованные по opt-in (152-ФЗ, контакты скрыты). Витрина + канал для работодателей. Отдельно от примеров, подключается на Шаге 3.

Статьи (блог) — третий контент-актив под информационные запросы.

## 2. Структура URL

```
/                              — лендинг
/primery/                      — каталог примеров (разделы)
/primery/[section]/            — раздел (напр. /primery/prodazhi/)
/primery/[section]/[profession]/ — пример резюме профессии (SEO-ядро)
/shablony/                     — галерея шаблонов
/shablony/[template]/          — страница шаблона
/baza/                         — База резюме (реальные, opt-in)
/baza/[section]/               — раздел Базы
/rezume/[publicToken]          — публичная страница конкретного резюме
/stati/                        — блог
/stati/[slug]/                 — статья
/faq/                          — FAQ
```

Слаги — транслит кириллицы (`prodazhi`, `menedzher-po-prodazham`). Хранятся в `CatalogSection.slug`, `CatalogProfession.slug`.

## 3. Шаблон страницы профессии (SEO-ядро)

Каждая из 500+ страниц `/primery/[section]/[profession]/` содержит:

- H1: «Резюме [профессия] — образец [год]»
- Готовый пример резюме (рендер шаблона на вымышленных данных профессии)
- Текстовый блок: что писать в опыте/навыках для этой профессии (уникальный текст под запрос)
- Кнопка «Создать своё резюме» (жёлтая CTA → конструктор с предзаполненной профессией)
- Перелинковка: соседние профессии раздела, ссылка на раздел, 3–5 связанных статей
- `metaTitle` / `metaDescription` — редактируются в админке, дефолт генерится из шаблона
- Разметка schema.org

Уникальность контента критична: 500 страниц-клонов Google понизит. Минимум — уникальный вводный текст + разные примеры данных на профессию.

## 4. Рендер и производительность

- **SSG + ISR** (Next.js). Страницы генерируются статически, ревалидация — при правке в админке (`revalidatePath`).
- Отдаются nginx-ом как статика → SEO-трафик не грузит Node (см. `ARCHITECTURE.md`).
- `sitemap.xml` — генерируется из БД (все секции, профессии, статьи, опубликованные резюме Базы). Разбивка на sitemap-index при >50k URL.
- `robots.txt` — открыт для примеров/статей; публичные резюме Базы — только с согласием, черновики и ЛК закрыты (`noindex`).

## 5. База резюме (реальные, Шаг 3)

- В индекс попадают только резюме с `isPublic && consentDistribution`.
- Карточка каталога: профессия, раздел, город, опыт, желаемая зарплата, дата обновления. **Без ФИО и контактов.**
- Контакты открываются роли `employer` (после входа). Обычный посетитель и поисковик их не видят.
- Email-подписка «новые резюме» по разделам: double opt-in, отписка в один клик (см. `data-model.md`, `Subscription`).
- Публичная страница резюме `/rezume/[publicToken]` — для paid бессрочна, для free отдаётся с `noindex` и живёт 24 ч.

## 6. Приоритет запуска

1. MVP: каркас каталога примеров (разделы + профессии), sitemap, меты из админки. Наполнение — приоритетные разделы (Продажи, IT, Логистика, Общепит, Админперсонал).
2. Статьи под информационные запросы (параллельно).
3. Шаг 3: База реальных резюме + подписка + доступ работодателя.
