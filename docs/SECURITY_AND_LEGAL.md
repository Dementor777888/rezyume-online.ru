# SECURITY_AND_LEGAL.md — безопасность, ПДн и юридические ограничения

## 1. Статус документа

Документ фиксирует технические требования к безопасности и обработке персональных данных.

Это не юридическая консультация. Перед публичным запуском формулировки согласий, политики и оферты нужно согласовать с юристом.

## 2. Типы данных в сервисе

Сервис обрабатывает персональные данные:

- ФИО;
- телефон;
- email;
- город;
- дата рождения;
- фото;
- история работы;
- образование;
- навыки;
- желаемая зарплата;
- публичная ссылка на резюме.

## 3. Два разных согласия

### Согласие на обработку ПДн

Нужно всегда, потому что без него сервис не может создать и обработать резюме.

Правила:

- обязательная галочка;
- выключена по умолчанию;
- без неё нельзя создать PDF/ссылку;
- фиксировать версию текста согласия;
- фиксировать дату принятия.

### Согласие на распространение ПДн

Нужно только для публикации в Базе резюме.

Правила:

- отдельная галочка;
- выключена по умолчанию;
- нельзя объединять с общим согласием;
- нужно явно объяснить, какие данные и где будут опубликованы;
- пользователь должен иметь возможность отозвать согласие.

## 4. Публикация в Базе резюме

По умолчанию резюме не попадает в Базу.

Для публикации нужны одновременно:

```text
Resume.isPublic = true
Resume.consentDistribution = true
Resume.consentAt != null
Resume.consentVersion != null
```

Контакты в Базе скрыты по умолчанию.

Карточка Базы может показывать:

- профессию;
- раздел;
- город;
- опыт;
- желаемую зарплату;
- дату обновления;
- навыки;
- краткое описание.

Карточка Базы не должна показывать без отдельного решения пользователя:

- телефон;
- email;
- Telegram;
- полный ФИО;
- точную дату рождения;
- фото.

## 5. Free/share-link и База резюме — разные вещи

Обычная публичная ссылка `/rezume/[publicToken]` нужна, чтобы пользователь мог отправить резюме работодателю.

База резюме `/baza/` — это каталог реальных резюме, где контакты скрыты и публикация возможна только по opt-in.

Нельзя автоматически добавлять free/share-link в Базу резюме.

## 6. SEO-примеры

SEO-примеры по профессиям должны использовать только вымышленные данные.

Правила:

- не брать реальные резюме пользователей;
- не копировать чужие резюме с HH/SuperJob;
- не использовать реальные телефоны/email;
- не использовать фото реальных людей без прав;
- данные должны выглядеть реалистично, но быть вымышленными.

## 7. Хранение данных

Production:

- MariaDB на сервере проекта;
- файлы на локальном диске сервера;
- сервер должен физически находиться в РФ для ПДн граждан РФ;
- внешние БД не использовать в MVP.

## 8. Пароли и сессии

Правила:

- bcrypt для hash пароля;
- password hash не возвращать в API;
- session только httpOnly cookie;
- cookie в production: `Secure`, `HttpOnly`, `SameSite=Lax`;
- recovery-token хранить в hash-виде или делать короткоживущим;
- одинаковый ответ recovery endpoint независимо от наличия email.

## 9. Anonymous edit token

Для anonymous free-резюме нужен отдельный `editToken`.

Правила:

- `publicToken` — только просмотр;
- `editToken` — редактирование;
- в БД хранить `editTokenHash`, не токен;
- `editToken` возвращать только один раз при создании;
- localStorage может хранить editToken на стороне пользователя.

## 10. Upload фото

Правила:

- максимум 15 MB;
- разрешить JPEG, PNG, WebP;
- очищать EXIF;
- не доверять имени файла;
- генерировать server-side имя;
- не давать выполнять загруженные файлы;
- хранить original и enhanced отдельно;
- AI-ошибка не должна блокировать экспорт резюме.

## 11. File download

Правила:

- нельзя отдавать произвольный path из query;
- fileName проверять strict whitelist-паттерном;
- PDF free можно скачать владельцу через editToken и по публичной ссылке;
- DOCX только paid владельцу;
- файлы чужих пользователей не должны открываться по перебору URL.

## 12. Webhook YooKassa

Правила:

- webhook не требует user session;
- webhook должен проверять событие и providerPaymentId;
- повторный webhook безопасен;
- все обновления payment/resume делать транзакционно;
- не логировать секреты и полные payload с ПДн;
- success активирует paid только для связанного Resume.

## 13. Rate limit

Защитить:

- `/api/photos/upload`;
- `/api/photos/enhance`;
- `/api/resumes/[id]/export/pdf`;
- `/api/resumes/[id]/export/docx`;
- `/api/payments/create`;
- `/api/auth/login`;
- `/api/auth/recover`.

В MVP достаточно простого in-memory или nginx limit_req. Если приложение работает в одном процессе pm2, in-memory допустим как первый этап.

## 14. Admin

Правила:

- отдельная роль `admin`;
- admin routes не индексируются;
- admin API требует session и роль;
- желательно IP allowlist через nginx;
- действия админки логируются без ПДн сверх необходимого.

## 15. Документы для запуска

До публичного запуска подготовить страницы:

- Политика конфиденциальности;
- Согласие на обработку ПДн;
- Согласие на распространение ПДн;
- Оферта;
- Правила возврата;
- Контакты и реквизиты;
- Страница поддержки;
- Политика cookies, если используются аналитика/маркетинговые cookies.

## 16. Возврат

Продуктовая политика: возврат без вопросов в течение 7 дней.

Технически нужно:

- фиксировать `Payment.status = refunded`;
- не удалять резюме автоматически без отдельного решения;
- дать admin-инструмент для ручной обработки возврата;
- не создавать негативный UX, похожий на скрытые подписки конкурентов.

## 17. Логи

Нельзя логировать:

- пароль;
- password hash;
- session cookie;
- recovery token;
- YooKassa secret;
- SMTP password;
- Gemini API key;
- полный телефон;
- полный email;
- полные тексты резюме в error logs.

Можно логировать:

- internal id;
- статус операции;
- код ошибки;
- masked email;
- masked phone;
- providerPaymentId без секретов.
