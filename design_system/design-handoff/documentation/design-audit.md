# Design Audit — «Резюме Онлайн»

Дата: 06.07.2026 · Аудитор: design QA / handoff review · Объект: design system + UI-кит сайта (16 экранов, десктоп+мобайл) + 7 шаблонов резюме.

## Этап 1. Резюме состояния

**Общая оценка готовности: 8/10 — готов к передаче в разработку** после исправления пунктов P1 ниже.

**Сильные стороны**
- Дисциплинированная токен-система: цвета с контраст-аннотациями прямо в токенах, 8px-сетка, мягкие тени, единые радиусы.
- Чёткое цветовое правило (yellow = действие, green = бренд, blue = иллюстрации) выдержано на маркетинговых экранах.
- Все 16 экранов существуют в десктоп+мобайл; ключевые флоу имеют состояния (loading/error/empty/success).
- Единый chrome (Header/Footer с foliage-волной) на всех публичных страницах; кликабельная навигация.
- Свободные и платные шаблоны резюме сознательно разведены визуально; контраст-verified акценты.
- Консистентные паттерны: сайдбар каталога (Образцы / База / Админ), sticky правая колонка деталей, чипы-фильтры, карточки.

**Главные риски**
1. **Ссылки-кнопки цветом `--brand-green` (#7CB342) на белом — контраст 2.6:1, WCAG AA fail** (см. Accessibility).
2. Смешение зелёных и жёлтых кнопок для действий (см. 2.4) — нужно зафиксировать конвенцию до разработки.
3. Мобильное меню-гамбургер в шапке — декорация, drawer не спроектирован.
4. Локальные дубли иконок и данных по файлам экранов (см. developer-notes) — риск рассинхронизации при верстке.

**Исправлено в ходе аудита**
- FAQ (десктоп): 5-й пункт сайдбара («Публикация в Базе резюме») переносился поверх карточки контента — убран `flex-wrap` у колонки. ✔

## Этап 2. Визуальный аудит UI

### 2.1 Композиция и сетка — OK, 3 замечания
- Единый контейнер 1180px и поля 40px/16px выдержаны на всех публичных экранах; админ — 1240px (осознанно шире). ✔
- Вертикальный ритм секций лендинга ~80px, карточные сетки на `grid gap 18–20px`. ✔
- **[P2] Превью-масштабирование**: шаблоны резюме масштабируются `transform: scale()`; там, где обёртка не ограничена по высоте, остаётся пустота (исправлено на Шаблоны/База/Превью; **Образцы → деталь исправлено в ходе аудита** ✔).
- **[P3] Админ**: карточки таблиц упираются в край на узких десктопах — допустимо для внутреннего инструмента.

### 2.2 Типографика — OK, 2 замечания
- Иерархия стабильна: hero 44/30, page-H1 30/24, H2 24, card-title 15.5–16, body 14.5–16, meta 12–13. ✔
- Playfair только в логотипе и 404-цифре; PT Serif только в «Академическом». ✔
- **[P2] Микро-кегли**: бейджи и меты 11–11.5px встречаются в карточках (AI-чип, «24 ч», счётчики). Рекомендация: минимум 12px.
- **[P3] Длина строк** в статьях ограничена 760px ✔; на FAQ-ответах ~800px — на грани, допустимо.

### 2.3 Цвета и контраст — 1 критичное
- Палитра чистая, случайных оттенков нет; «внесистемные» литералы (#FDF0DA, #8A5A0E, #B4451E…) повторяются согласованно — вынесены в `tokens/colors.json → ui-kit-extras` для кодификации.
- **[P1, a11y] Зелёные текст-ссылки `#7CB342` на белом = 2.6:1.** Употребляется массово («Смотреть шаблон →», «Взять за основу →», ссылки в статьях, «Открыть FAQ →»). Фикс: текст-ссылки переводить на `--brand-green-dark #3F6B22` (5.6:1); #7CB342 оставить для заливок, бордеров, крупных декоративных акцентов.
- **[P2] Заголовочный акцент «первый отбор»** зелёным на белом (2.6:1) — крупный шрифт, формально проходит AA Large только с 3:1; чуть темнее (#5c9032+) решит.
- **[P3] Админ: синяя кнопка «Сгенерировать»** (#2D6685) повторяет референс заказчика, но нарушает правило «blue never on buttons». Оставлено намеренно (внутренний инструмент, соответствие скрину) — задокументировано.
- Ошибки/успех/предупреждение: #B4451E на #FBEDE7, #3F6B22 на #DCEDB9, #8A5A0E на #FDF0DA — все ≥4.5:1. ✔

### 2.4 Компоненты — 2 замечания
- Библиотека (Button, Badge, Card, Input, Select, Checkbox, Radio, Switch, Tabs, SkillBar) единообразна, используется через `window.DS` повсеместно. ✔
- **[P1, зафиксировать конвенцию]** В UI-ките сложилась фактическая система кнопок: **yellow (primary) = конверсионное/платное действие**, **green (secondary) = бесплатное продолжение** («Сохранить фото», «Продолжить к оплате», «Далее»), outline/ghost = навигация. Это расходится с буквой брендбука («yellow — единственный action-цвет»). Решение нужно до разработки; рекомендация — принять фактическую конвенцию и записать в брендбук (она информативна: цвет = стоимость действия).
- **[P2] Состояния компонентов**: hover заданы в DS-компонентах; **focus-ring и disabled описаны только у Button/Input**. Перед версткой добавить focus-visible спецификацию для Checkbox/Radio/Switch/Tabs (см. component-spec.md).
- Дубликатов компонентов нет; локальные однотипные карточки экранов (ArtCard, Card в База/Образцы) — кандидаты в один `CatalogCard` (см. component-spec).

### 2.5 Иконки и изображения — 2 замечания
- Стиль единый: stroke 2px, скругления round, 15–26px. ✔ Фичи «Под вакансию»/«Письмо» унифицированы через общий `SITE.FeatIcon`.
- **[P2] Пять локальных наборов иконок** (FIcon/CIcon/PIcon/NIcon/ActIcon) дублируют глифы sparkle/doc/mic. Для разработки консолидировать в один модуль (см. developer-notes).
- Изображения: единственный растр — hero-portrait (плейсхолдер кандидата); логотипы — PNG-кропы из референса, foliage — вектор. ✔ Обложки статей — паттерн-плейсхолдеры, помечены как «обложка статьи» — реальные иллюстрации предоставляет заказчик.

### 2.6 Состояния интерфейса — покрытие и пробелы
Есть: Конструктор (default/saving/error), Фото (default/empty/loading), Превью (default/loading/error), Оплата (flow/loading/declined/success), Кабинет (default/empty), Вход (default/error/loading/recover), Публичная ссылка (free/paid), Поддержка (form/success), Админ (promo/content).

**Добавить до/во время разработки [P2]:**
1. Ошибки валидации полей Конструктора (пустое имя, кривой email) — есть только ошибка сохранения.
2. Empty-состояния каталогов: Образцы/База/Статьи при пустом фильтре (в FAQ поиск «ничего не найдено» есть ✔, в админ-таблицах есть ✔).
3. Loading-скелетоны каталожных сеток.
4. Состояние «файл слишком большой / не тот формат» для загрузки фото и импорта старого резюме.
5. Обрезка длинных строк: длинное ФИО в шапке резюме, длинный заголовок статьи в карточке (сейчас не ограничены, `-webkit-line-clamp` на усмотрение верстки).

## Этап 3. UX-аудит

- Главный сценарий (лендинг → конструктор 6 шагов → фото → превью → оплата → кабинет) читается без пояснений; прогресс-бар и кликабельные шаги ✔.
- CTA очевидны: один жёлтый акцент на экран ✔. После клика понятно, что будет («Скачать PDF — бесплатно», «Усилить резюме за 99 ₽» — цена в кнопке ✔).
- Обратная связь: автосейв-индикатор в конструкторе, тосты в админке, success-экраны ✔.
- **[P1] Чекбокс согласия в Поддержке предотмечен** — юридически согласие должно быть активным действием. Снять default-check.
- **[P2] Мобильный гамбургер не открывает меню** — спроектировать drawer (список = NAV + Вход + CTA).
- **[P2] «Забыли пароль?»** — состояние recover есть у Входа ✔, но переход из ошибки логина в recover не подсвечен — мелочь, на усмотрение.
- **[P3] Конструктор шаг 1 стал длинным** (импорт-блок + 7 полей + «О себе» + AI-диктовка): на мобайле много скролла. Вариант: свернуть импорт-блок в одну строку-ссылку.
- Названия разделов однозначны; «Образцы» vs «Шаблоны» разведены по смыслу (контент vs оформление) ✔ — сохранить это разделение в текстах при разработке.

Приоритеты: P1 — согласие в Поддержке; P2 — мобильный drawer, валидация форм.

## Этап 4. Адаптивность

Смотри `responsive-rules.md` — там полные правила для верстки. Ключевое:
- Макеты в 2 точках: 1320/1180 и 390. Планшет закрыт `auto-fill`-сетками и правилом сворачивания сайдбаров; отдельные планшетные макеты **не требуются**, но нужен ручной прогон 768–1024.
- Все fixed-элементы мобайла (нижняя панель конструктора) не перекрывают контент — предусмотрен паддинг ✔.
- Touch-цели: основные кнопки ≥44px ✔; **[P2] иконки-действия в админ-таблицах 30px** — допустимо для десктоп-инструмента, но на мобайле увеличить до 40–44px.
- Горизонтальных скроллов не осталось (проверены: Превью+экспорт, промо-таблица админки — исправлены ранее).
